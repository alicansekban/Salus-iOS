## Recorded iOS divergences (decided now, carried by every task)

- (a) `SalusGradient` is a `struct` with `top`/`bottom` `Color` + a `vertical` `LinearGradient` accessor — Swift has no `Brush`; the Android `(top, bottom)` naming is kept verbatim.
- (b) Segmented controls: Android's `SingleChoiceSegmentedButtonRow` → `Picker().pickerStyle(.segmented)` (the established VitalsScreen mapping); sex icons inside segments have no direct SwiftUI equivalent — the sex picker shows text labels only, and the icons' removal is accepted (Android itself dropped the per-sex accent colours in M12).
- (c) `SalusProgressRing` wraps `ProgressView(value:)` with `circularProgressViewStyle` tinted white on a 0.24-alpha white track — SwiftUI has no raw `CircularProgressIndicator`-equivalent stroke API at the same fidelity; the label sits centered over it.
- (d) The dose-progress caption and ring duplicate the Android wording exactly; `Text(verbatim:)` everywhere.
- (e) The medications count chip: iOS `xcstrings` plural handling differs — use `medications_count` as two variants selected by count in code (`String(format:)` with `%1$lld ilaç` / `%1$lld medication(s)` resolved from two keys `medications_count` + `medications_count_one` — Android's `plurals` twin, recorded divergence).
- (f) The cycle back button: iOS pushed screens get the system back button from `NavigationStack` automatically — the M4/M6/M8 precedent (`settings_back` dropped, the shell draws it). Task 8's twin is therefore *verification-only*: confirm the cycle calendar is a pushed destination (tab bar hidden, system back present) and write the QA row; no code unless the push wiring is missing.
- (g) Home's hero white text: `.foregroundStyle(.white)` — Android's `Color.White` — and `.white.opacity(0.9)` for the date line; contrast pairs already verified in the Android final review.
