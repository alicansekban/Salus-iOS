# iOS-M1 — Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Executor subagents run on **Opus** (user preference). This plan is deliberately compact: it specifies contracts and behaviour, not source code — the executor writes the code against the named Kotlin sources, which are the spec. Read `CLAUDE.md` and the M0 plan's "Execution record" first.

**Goal:** The non-UI core of the app exists and is proven against Android: the domain vocabulary, the time/id/undo primitives, a GRDB database whose schema is byte-equivalent to Room schema v3 with migrations from v1, the 13-key settings store, the profile repository, and a composition root that boots all of it under a five-tab shell with per-tab `NavigationStack`.

**Architecture:** Each package is a hand-port of its Gradle twin (`:core:model`, `:core:common`, `:core:testing`, `:core:database`, `:core:datastore`, `:core:profile`, `:core:navigation`, `:app` DI). Android tests are carried over as the drift detector. GRDB is the first and only third-party dependency this milestone adds. DAOs beyond profile arrive with their features (M2+); M1 ships the schema, the records and the migration machinery they will sit on.

**Tech Stack:** Swift 6 / Swift Testing · GRDB.swift 7.x (SPM) · UserDefaults + Keychain (Security.framework) · SwiftUI shell · XcodeGen.

**Spec:** `../salus-android/docs/ios-v1-plan.md` §4, §5, §9, §10 (iOS-M1), §6.1 (constants only) · Room contract `salus-android/core/database/schemas/com.alicansekban.salus.core.database.SalusDatabase/{1,2,3}.json` · Kotlin sources named per task.

## Global Constraints

- iOS 17.0, Swift 6 strict concurrency, bundle id `com.alicansekban.salus`; `.macOS(.v14)` only where M0 already has it (none of the M1 packages need it — GRDB builds on the host as is).
- **Exactly one new dependency: GRDB.swift** (`https://github.com/groue/GRDB.swift`, pinned `from: "7.x"` — the latest 7.x tag at execution time, recorded in README). Nothing else. Declared only in `Packages/SalusDatabase/Package.swift`.
- Every persisted string is Android-verbatim: table/column/index names from the Room JSON, enum raw values = Kotlin constant names, the 13 settings keys (spec §9), `salus.db`, `default-profile`.
- `SalusModel` stays Foundation-free where possible (no `Date`, no `Calendar` — epoch days and minutes-of-day are `Int`); `SalusModel`/`SalusCommon` never import UI frameworks (lint rule already enforces).
- No user-facing strings in M1 (no String Catalog yet). English code comments that cite the Kotlin file:line they port.
- One branch `m1-core`, one commit per task, `scripts/ci.sh` green before every commit that touches a manifest or `project.yml`.

### Rulings made during execution (decided on the user's behalf — read these)

- `DatabaseQueue` for file and in-memory databases; a pool can replace it later without API change.
- `.macOS(.v14)` spread from 12 to 20 packages: GRDB floors macOS at 10.15 (SalusDatabase + 3
  dependents) and `@Observable` is macOS 14+ (SalusCommon, SalusTesting, SalusSettings,
  SalusNavigation). Host `swift test` cannot build otherwise; `CLAUDE.md` lists the three reasons.
- No CI SPM cache: cold `build-app` with GRDB measured at 54 s (< 2 min threshold).
- `DispatcherProvider` has no Swift twin; `PendingDeleteController.commitNow/commitAll` are `async`
  (no `scope.launch` twin) and take an injected `sleep` for deterministic tests.
- Kotlin `Long` → `Int64` in records (the plan's "plain Int" wording was wrong).
- Column order is not compared by the schema-parity test (`ALTER TABLE` appends; Room's own
  validator is name-keyed).
- `observe*` streams are `AsyncThrowingStream<T, any Error>` with `.bufferingNewest(1)` — Kotlin
  `Flow` throws and Room conflates; the plan's `AsyncStream` wording is superseded. Applies to
  `ProfileDao.observeDefaultProfile` and `ProfileRepository.observeProfile`.
- Only `ProfileDao` ships in M1; feature DAOs arrive with their features on the 13 proven records.
- No Koin-module twins: `AppCompositionRoot` owns every singleton; `UserDefaults.standard` replaces
  Android's `salus_settings` suite (documented on `SalusPreferencesDataSource`); only
  `app_lock_enabled` lives in Keychain; the real Keychain store is untested on the host.
- `ProfileRepositoryImpl` is `internal` behind `makeProfileRepository(database:clock:)`.
- `TabBackStacks` is generic and lives in `SalusNavigation` (the App target has no test bundle);
  theme injection is `EnvironmentValues.salusTheme` via `@Entry` (SwiftFormat rewrites the long
  form); DB open failure is log + `fatalError`.
- Re-selecting the current tab is a **no-op** (`TopLevelBackStack.kt:30-35`); the plan's "pops to
  root" was a plan defect, fixed in Task 7's fix round.
- `.background` commit of pending deletes is wrapped in `beginBackgroundTask`/`endBackgroundTask`.
- An Xcode-authored `DEVELOPMENT_TEAM` write into the pbxproj was reverted, not adopted: signing
  configuration arrives with the device/TestFlight milestone.
