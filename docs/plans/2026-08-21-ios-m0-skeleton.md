# iOS-M0 — Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Executor subagents run on **Opus** (user preference). This plan is deliberately compact: it specifies contracts and behaviour, not source code — the executor writes the code against the named specs.

**Goal:** A themed empty shell that builds, tests, lints and launches on the iOS 26.4 simulator, with the full 24-package SPM graph, design tokens transcribed 1:1 from Android, and CI green on GitHub Actions.

**Architecture:** Local SPM packages inside one Xcode workspace, mirroring the Gradle modules one-for-one (spec §4). The `.xcodeproj` is generated by XcodeGen from `project.yml` so the project file is never hand-edited. `SalusDesignSystem` contains tokens only, no views.

**Tech Stack:** Xcode 26.4.1 · Swift 6 / SwiftUI · iOS 17.0 deployment target · XcodeGen · SwiftLint + SwiftFormat · GitHub Actions (macOS runner).

**Spec:** `../salus-android/docs/ios-v1-plan.md` (§4 module structure, §10 iOS-M0, §6 decisions) and `../salus-android/docs/design/design-tokens.md` (the token contract: 213 tokens, each with Kotlin source line + SwiftUI equivalent, 5 FeatureAccents).

## Global Constraints

- Deployment target **iOS 17.0**; bundle id **`com.alicansekban.salus`** (spec §3).
- Dependencies **SPM only**; M0 adds **zero** third-party dependencies (GRDB/RevenueCat/Firebase arrive in later milestones).
- Package names and module mapping exactly as spec §4 (24 packages incl. `SalusBackup`; Features under `Packages/Features/`).
- **Features never depend on each other**; `SalusModel` links no UI framework — the graph must make this structurally impossible, not conventional.
- Every token value transcribed, never invented: source of truth is `design-tokens.md`. Turkish is the development language later (§6.4) but M0 ships no user-facing strings.
- Commit per task, linear history on `main`, same git discipline as Android.
