# Room schema exports (test fixtures)

`1.json`, `2.json` and `3.json` are **verbatim copies** — byte for byte, no reformatting — of
Room's exported schema for the Android database:

    salus-android/core/database/schemas/com.alicansekban.salus.core.database.SalusDatabase/{1,2,3}.json

They are the contract `RoomSchemaParityTests` checks the GRDB migrator against: after migrating a
fresh database up to `"v{n}"`, the tables, columns, indices and foreign keys must be exactly what
`{n}.json` describes. Nothing in the iOS sources may be the source of truth for the schema — the
Android export is.

**Re-copy on every Android schema bump.** A new `4.json` on Android means: copy all four files here
again (the earlier ones can be regenerated by Room and are not guaranteed to be untouched), add the
matching `"v4"` migration, and extend the parity test's version list. A schema change that lands on
one platform only is a bug, not a port decision.
